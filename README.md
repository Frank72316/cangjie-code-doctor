# Cangjie Code Doctor

基于编译反馈与知识检索的仓颉程序诊断与测试验证工具。

面向仓颉学习者与初级开发者，将错误定位、文档查询、修改建议和测试验证组织为一条可追踪的流程。项目由三人团队在一个学期内完成，核心业务、工具调度与数据处理使用仓颉实现。

> 当前阶段：需求与方案设计。仓库目前包含项目说明，尚未实现诊断、修复或验证功能，也没有可运行的安装命令。

## 项目说明

阅读完整的 [项目说明与团队分工（PDF）](docs/project-brief.pdf)，其中包含功能需求、技术方案、模块接口、三人职责、12 周计划和验收建议。

项目仓库：[GitHub](https://github.com/Frank72316/cangjie-code-doctor) · [AtomGit / GitCode](https://gitcode.com/A72316/cangjie-code-doctor)。两边均为公开仓库。

## 使用流程

导入仓颉源码及测试用例 → 编译并定位错误 → 检索对应版本文档 → 生成修改建议 → 用户选择应用 → 编译与测试验证 → 输出报告。

首版范围限定为课程知识范围内的单文件仓颉程序，统一 SDK 版本及目标运行环境。

## 计划功能

- [ ] 项目导入、任务目录及原始源码留存
- [ ] 编译器调用与结构化诊断信息
- [ ] 固定版本官方文档的检索与来源定位
- [ ] 模型修改建议、响应校验与代码差异展示
- [ ] 隔离环境中的编译、测试、资源限制及超时处理
- [ ] 本地报告、原始日志与每轮修改记录
- [ ] 批量评测和最多两轮的修复流程
- [ ] 可选扩展：小型多文件工程或额外检索策略

编译通过与测试通过分别记录。测试通过仅代表满足当前测试集，不能视为已证明程序完全正确。

## 技术方案

| 模块 | 职责 |
| --- | --- |
| 任务与文件管理 | 输入副本、任务状态、版本和配置记录 |
| 编译与测试执行 | 固定参数调用、执行隔离、状态采集及超时处理 |
| 诊断解析 | 文件与行列定位、错误分类、原始日志保留 |
| 文档检索 | 文档分段、关键词索引、排序与来源映射 |
| 修复协调 | 模型请求、输出校验、修改副本、轮次控制 |
| 报告与评测 | 轨迹展示、批量统计、对照实验与失败分析 |

先完成命令行流程，再增加本地展示界面。CangjieMagic 是可选基础框架；SDK、扩展库与框架版本将在第一阶段验证并锁定。

## 评测设计

计划建立 60-100 个分类错误案例，分离开发集与最终评测集，并比较三种配置：

1. 源码、题意与初始诊断直接输入模型。
2. 在上述输入中加入对应版本文档检索结果。
3. 在检索基础上，后续修复轮次加入实际编译反馈。

控制模型、参数、案例及最大调用轮数，报告编译成功率、测试验证成功率、耗时、调用数及 token 用量。最终保留测试不输入模型。效果与失败情况如实记录，不预设性能提升结论。

## 开发约定

- 先验证单一环境和单文件流程，再扩展功能。
- 不提交模型 API 密钥、账号信息、个人配置或未经允许的源码。
- 执行输入程序须使用经过验证的隔离环境；隔离完成前仅运行自建可信案例。
- 明确标注开源复用范围与许可证，记录自主实现部分。
- 修改共享接口时同步团队，并补充对应测试。

## 两个平台的协作与同步

当前设置为本地分别推送到两个远程仓库，没有启用后台自动同步。

- `origin`：GitHub，保留为当前主协作入口。
- `atomgit`：AtomGit / GitCode，保存相同的 `main` 分支提交。
- 建议队友统一在 GitHub 提交合并请求；合并后拉取最新 `main`，再推送到 AtomGit。后续也可以由团队统一切换主平台。
- Git 推送同步指定分支的代码、文档及提交历史；Issue、合并请求、评论和仓库设置不会随之同步。
- 一个平台推送失败时，另一个平台可能已成功。解决失败原因后补推即可，遇到分支分歧先检查和合并，不使用强制推送覆盖队友提交。

队友从 GitHub 克隆后，添加第二个远程地址（远程配置不会随克隆复制）：

```sh
git clone https://github.com/Frank72316/cangjie-code-doctor.git
cd cangjie-code-doctor
git remote add atomgit https://gitcode.com/A72316/cangjie-code-doctor.git
```

同步主分支时，先确保本地工作已保存并切换到 `main`，再运行：

```sh
git pull --ff-only origin main
git push origin main
git push atomgit main
```

两个平台需要各自的登录凭据和推送权限；公开访问只代表可以查看和克隆，不代表任何人都能推送。团队开发分支和标签需要按需另外推送。
