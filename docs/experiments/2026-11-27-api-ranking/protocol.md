# 标准库 API 排序能否改善仓颉程序修复

上轮实验发现，指定相关条目和自动选段在两道码点题上表现不同。本轮将上轮 12 题全部作为开发集。先冻结排序器，再编写新的 12 道函数修复题。评估题和目标条目在运行两种检索、调用模型之前封存并提交。所有题由同一研究者设计，属于定向迁移测试。

## 研究问题与对照

两组使用相同的 SDK 1.0.5、218 个 API 条目、两段通用指南、提示、模型和编译反馈。第三段文档是组间唯一可以不同的请求字段。B 为上轮原生 BM25 的 API 第一名。F 为实验排序，按题意做中英文概念匹配，方法名、签名、说明的权重分别为 4、1.5、1，按语料逆文档频率加权。公共词表覆盖码点、字节、前后缀等概念；函数形参类型命中条目所属类型时加 2 分。它在本地遍历全部条目，使用题意和函数签名。它没有评估题 ID、标签或参考解，也不使用模型。基线保留上轮查询，因此差别包含查询构造与字段打分两项。

新题分成两层，各 6 题。一层复用开发集中出现过的目标 API，另一层指定开发集中没有标注过的目标 API。每道题预先指定一个能完成核心操作的条目。首位及前 3 位精确命中为检索指标，也保存完整条目名供人工解释。不同方法也可能得到正确程序。

主要指标是各组一次生成后通过公开和保留测试的次数，每题各组重复 3 次。共 72 次独立请求。每题成对执行，两组先后顺序随题号和重复号交替。保留成功、编译失败、公开失败、保留失败、格式问题和违规源码各自记录。相同提示的重复也计入原定分母。比较 F−B，同时列出分层结果、逐题改善/持平/退步、按两层分别按题重采样 10000 次的探索性 95% 百分位区间（种子 20261127）。不按结果删题、换答案、追加重试。开发集成绩单列。

付费前在 GitHub Linux 固定 SDK 中验证每道题的错误原程序、参考实现及两套行为测试；材料错误先公开记录并复验。全部候选锁定后才运行候选保留评分。SDK 与上一轮一致。模型 deepseek-flash，关闭思考，temperature 0、top_p 1、4096 最大输出 tokens。沿用累计 20 元授权，既有实验估算 2.767942 元，另保留 1 元既有开发余量。本轮最多预留 5 元，72 次请求合计的最坏估算须低于该值。费用用高峰非缓存价估算。交易和 API Key 仅在本机。[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

本轮是实验排序器评估，工作台是否采用取决于结果。关于学生实际表现，需要不同的研究设计。
