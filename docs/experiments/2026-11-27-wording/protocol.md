# 用日常表述修复仓颉程序：题意与文档的交叉对照

上一轮 12 份作者改述只参与了检索。此次使用同一批已封存的题、两种等价表述、源码、24 组公开输入、120 组保留输入和原评分规则。复核材料 SHA 和 48 份 SDK 1.0.5 隔离验收报告。研究单位是六对任务；熟悉这些案例的研究者继续复核，不能当作新题或真实学生样本。[上一轮报告](../2026-11-27-operation/report.md)

## 六种输入

F 表示原来的技术表述，N 表示作者事先写好的日常表述。组名首字母表示模型看到的题面，第二个字母表示补充文档的来源。所有组的两条通用指南由错误程序标识符和编译诊断检索，不使用任一版题面。它们在同一道题的所有条件中逐字相同。

| 组别 | 模型看到 | 补充材料 |
|---|---|---|
| FF | 技术表述 | 按技术表述选出的第一段 API 文档 |
| FN | 技术表述 | 按日常表述选出的第一段 API 文档 |
| NF | 日常表述 | 按技术表述选出的第一段 API 文档 |
| NN | 日常表述 | 按日常表述选出的第一段 API 文档 |
| NS | 日常表述 | 从错误函数识别集合类型，提供该类型在固定语料内的全部成员声明 |
| NG | 日常表述 | 仅两条共同指南 |

四格交叉重用上一轮冻结的检索算法，本轮重新调用模型。NF 是人为控制的文档替换，单有日常描述的系统无法获取配对原题。NS 不用技术题面、标准答案或案例标签。按官方文档顺序摘出签名，保留参数、返回类型、属性与方法的区别。若无法辨认唯一接收类型，NS 退回 NN。签名清单和单段文档的信息量、格式及 token 数不同，测量其整体使用效果。

## 付费前锁定的分析

主要比较为 NF−NN（同一日常题面，更换检索所用表述）、FF−NF（固定技术表述检索出的文档，更换模型题面）和 NS−NN（实际可提供的类型签名清单）。同时列出 NN−NG、FN 与其余交叉格，以及交互差 (FF−FN)−(NF−NN)。报告六对逐对成绩、相同/不同 API 条目的分层、候选编译/公开/保留状态、输入输出 tokens 与费用。以六对题为抽样单位，枚举全部 6^6 次有放回的重采样，给出描述性 95% 百分位区间。即使差异很小或方向相反也保留。不进行多重检验显著性宣称。

每题每组独立生成两次，12 × 6 × 2 共 144 次。组序按六条件平衡轮换；仅重跑隔离设施中断，不再向模型索要新答案。SDK、系统消息、模型和生成参数与上一轮相同。保留材料、标签、历史候选和成绩不进入模型请求。去除组别后复核完整源码，模型候选只在 GitHub Linux 固定 SDK 容器执行。通过须满足公开和保留测试以及契约复核。

已累计保守估算 3.932676 元。本轮最多预留 8 元，另留 1 元既有开发余量，在 20 元累计授权内。144 个请求的逐项最坏额度须在调用前通过校验。模型使用 deepseek-flash、关闭思考、温度 0，输出上限 4096 tokens。费用按高峰非缓存口径及实际时段缓存口径分别估算。[DeepSeek 定价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
