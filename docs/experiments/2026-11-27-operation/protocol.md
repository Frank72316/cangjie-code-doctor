# 从集合类型到具体操作：配对修复实验

上一轮把正确集合排在首位的题数从 7/12 提到 11/12，但具体方法的首位命中仍只有 1/12。本轮先冻结新规则，再写新题。既有七对检索短句和十二道集合题全部视为开发材料。语料沿用同一 SDK 1.0.5 的 203 条官方文档。[语料与来源](../2026-11-27-api-families/sources.json)

**干预。** T 沿用类型前置排序；I 只在识别到唯一接收类型和有效动作时，按中文题意识别查看、删除、插入或定向遍历，再在这个类型内比较方法名及官方说明所支持的动作和方向。同一档保留原顺序。不向模型添加标签、推理说明或正确方法名。G 只给两段通用指南，用于衡量加入一段具体 API 文档相对不加这一段的变化。T、I 除第三段文档外所有输入都相同。

**材料。** 设计六对相近任务共十二题，每对共享完全相同的错误函数体，目标行为在方向或是否更改状态上有差别。选择 ArrayDeque、TreeMap 以及此前未作为修复题目标的 ArrayQueue、LinkedList。每题事先写两种自然中文表述，原表述用于模型，改述仅作检索复测。两种表述均不提供英文方法名。先封存可接受 API 标签和不公开的行为断言，评分同时检查返回值和调用后的对象。SDK 隔离验收要求每个参考两套检查均过，每个原程序两套均失败。由同一研究者设计与核对，结论限于这些定向任务。

**指标。** 主要检索指标为第一条可接受文档命中数，并列前三命中、改述命中、同一对两题都命中、两种表述都命中。主要修复指标为一次生成同时通过公开与保留测试并通过契约复核。各组每题两次，三组共 72 次。交错六对任务，轮换三组调用顺序；不根据结果追问模型。报告 I−T、I−G 的通过数及逐对差值，按六对为单位精确枚举有放回重采样的探索性百分位区间，重复输出不当作独立题。若改述失效或程序通过数没有提高，照实记录。默认工作台上线另行判断。

**费用。** 模型 deepseek-flash，关闭思考，温度 0，单次最多 4096 输出 tokens。冻结请求后逐项计算最坏预留，最多 5 元。既有实验保守估算 3.472668 元，另留 1 元开发余量，累计上限 20 元。使用 SDK 固定的 Linux 容器执行候选，模型密钥留在本机。[官方计价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
