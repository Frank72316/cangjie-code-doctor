# 未见集合类型的文档检索与修复实验

问题是从错误代码识别方法所属的集合类型，能否帮助检索具体方法，以及模型能否据此更常修对。以未进入上一轮 API 语料的 ArrayDeque、ArrayStack、TreeMap、TreeSet 为四个家族，每类新编三题。题目只代表定向迁移场景。作者兼任出题和标注，独立性有限。

F 重用上一轮字段排序。T 在 F 的完整排名上，仅当目标函数内存在唯一可识别的成员访问接收类型时，将该类型的条目稳定前置；无证据或多类型时保持原序。只读错误函数的形参、局部声明和成员访问，不读主函数。两组共用一份来自固定版本官方文档的语料。额外报告原生 BM25 检索，不为它购买模型调用。覆盖九种集合的全部可提取 API，包括有同名方法的干扰类型。上轮 218 条与本轮语料不同，跨轮成绩不可直接相减。

在计算新题排名前锁定案例、可接受的条目集合、首选条目及边界测试。在取得付费模型回答前用 SDK 1.0.5 隔离检查所有原程序和参考程序。主检索指标为前一名是否属于可接受集合，另报前三、首选精确命中、类型命中。备选项须能直接支持核心操作，通用清空或仅查看容量不算。模型主指标为一次生成通过公开、保留行为测试并经契约复核，每题每组两次；检索条目相同也保留独立调用。报告 T−F 的逐题差值、改变文档/相同文档的组内结果及四个家族分别的结果。以家族为单位重采样四次，枚举全部 256 种有放回组合，给出探索性百分位区间。四个家族不足以推断学生程序的总体效果。若文档排名提升而修复持平或下降，分别报告两个结果。

两组的 SDK、两段通用指南、公开反馈、模型参数相同，仅第三段 API 文档随检索器改变。按家族交错题目，重复时对调先后次序。沿用 deepseek-flash、temperature 0、关闭思考、4096 最大输出，禁重试。最多 48 次，本轮预留上限 4 元，累计既有估算 3.190156 元，另保留 1 元开发余量，累计上限 20 元。先密封独立参考与保留测试，再锁输入和候选，使用已有 Linux 隔离评分。按高峰非缓存 token 价格估算，单独报告新增费用。[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
