# 一条真实边界反馈能否改善仓颉修复？

预登记时间为 2026-11-28，材料验收和本轮模型调用前。主问题是：在相同的边界复查提示上，增加一个给出期望值和真实运行结果的例子，能否提高未展示输入的全部通过率？

## 题目与分组

主样本沿用上轮按固定规则选取的 24 份链表初稿，六类操作各分左右方向、整表与位置任务。另设 8 道新数组题，覆盖连续区间、前缀、位置查找和局部修改。数组初稿由研究者编写，包括正确实现，单独作为小规模迁移检查。各组逐题使用相同初稿、题意、文档和原公开反馈。

- H 给出边界复查提醒。
- S 额外给出一个具体输入和按照题意应有的返回值、最终序列。
- R 在 S 的同一例子上追加隔离环境实测的返回值和最终序列。如初稿未能运行则只报告真实状态。

主比较为 R 减 H；S 减 H 衡量展示具体例子的增量，R 减 S 衡量已知期望时实测反馈的增量。每题每组独立请求两次，组内均允许保留初稿，模型、温度、最大输出和已有文档固定。六种组序轮换，第二遍反向遍历题目、反转每题组序。共 192 次真实调用。累计保守费用从 6.541592 元起算，本轮预留上限 10 元，遵守历轮 20 元总限额。

## 冻结与评分

每道链表题统一展示空表，每道数组题统一展示阈值等于唯一元素的单元素输入。选例规则与初稿是否通过无关。参考实现和初稿在固定 SDK 1.0.5 Linux 容器中分别运行，SDK 参考输出必须符合独立数组计算结果。先冻结输入及密封的保留材料，再验收材料和冻结请求，最后生成候选，盲审后评分。不按反馈失败筛题，不重抽失败回答。

主指标为编译、原公开样例和全部 18 个未展示输入通过。每题的新保留输入均与本题公开和诊断输入完全不同，链表部分还与前两轮保留输入去重。另记录候选在展示样例上的成绩，二者分别判定。按题和操作家族展开，重复次数不视为独立题数。报告与初稿比较的修对和改坏数、仅通过展示样例却未通过保留的数量、公开通过且与展示输入不同长度类别的保留检查通过数。一次都未完成的检查按失败计，工具故障中止并保留证据。

主样本按六个操作家族分别去掉一个重算 R−H，观察收益有无集中于单一家族。八道人工数组题单列。若 R 与 S 接近，将直接报告实测输出在已经提供正确预期时增量有限。每道题复核者为同一人，本轮不用于推断真实学生的受益率。
