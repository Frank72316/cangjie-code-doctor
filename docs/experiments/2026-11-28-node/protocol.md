# 链表节点与可空值的文档对照

上轮将整张 LinkedList 成员签名给模型后，左侧书签插入两次都编译失败。候选已找到插入方法，仍直接读取可空节点的成员。本轮用八道新题检查两种文档能分别帮多少忙。每题从调用方给出的可空游标出发，覆盖读取邻项、沿一侧加权读取、修改邻项、隔一个位置插入。每种操作各有向前和向后两题。这个刻意集中在游标的任务集用于检验上述机制。

| 组 | 全部组均有 LinkedList 成员清单，另外给 |
|---|---|
| L | 无 |
| N | LinkedListNode 的 next、prev 和 value 三个官方声明 |
| O | 官方指南里处理 Option 的 match/Some/None 示例 |
| B | 同时给 N 和 O 的材料 |

每题每组独立生成两次，共 64 次。用四阶平衡顺序，固定同一模型、参数、SDK、题面、错误源码与原程序反馈。节点和示例文档对所有题相同。主要结果为 B−L，其余报告 N−L、O−L、B−N、B−O 及交互差。按四个操作对展示净变化与逐题次数。方向对和重复生成均有关联，避免把 64 份当作 64 道独立题。如有持平、倒退或天花板效应，照实呈现。

冻结参考程序、公开输入和保留断言后，先在 Linux 隔离容器检查每题原程序两套检查失败、参考程序两套通过，再锁定请求并调用模型。评分检查返回值及整张链表的值与顺序，不限制解法。模型不接触保留输入或参考解。候选按组别遮盖审阅后锁定，再用原隔离评分入口判定。记录编译、公开和保留三个阶段及真实用量。单一模型，研究者独立编题，无学生样本。
