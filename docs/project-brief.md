# 仓颉程序诊断助手项目说明与团队分工

正式名称：仓颉程序诊断与测试验证工具（Cangjie Code Doctor）。修订日期：2026-10-21。当前为开题方案，尚无实现或实验成绩。

## 项目问题与交付

核心问题是：加入同版本官方文档检索，仓颉课程程序的修复成功率是否发生变化？通过可操作的诊断工具承载受控 A/B，同时交付源码、冻结案例与协议、原始记录、配对结果和失败分析。

用户流程为报错定位、核对文档解释、确认修改副本、测试验证、查看历史或回退。本地 Web 与批量实验入口均须交付；核心业务使用仓颉实现。首版限定固定 SDK、不超过 200 行、仅标准库的单文件练习，采用确定性标准输入输出测试，首周锁定 Linux 容器环境。没有有效测试时标记“行为未验证”。

## 实验及结论边界

拟准备 30 例，10 例开发、20 例评估。评估集含 16 个错误：语法、类型、作用域或接口误用、可编译逻辑错误各 4 个；另 4 个正确案例做回归检查。

A 组使用题意、代码、公开测试和初始执行结果，B 组仅额外使用同版本文档。两组同模型、同参数、同反馈与停止规则，最多两轮；每个错误每组运行一次，计划最多 64 次生成，故障重跑另计。主实验不允许人工改写或补充提示。

第六周冻结案例、文档、配置、规则及工具版本。全部候选锁定后才使用保留测试。主指标为编译成功且全部公开与保留测试通过的成功数 / 16，同时报告四种配对成败、差值和成本。4 个正确案例单列，不混入修复率。

若 B 较好、接近或较差，均完整报告。无明显改善时说明“本次未观察到明确优势”，核对具体失败和检索证据；不删除不利结果，不把试用体验当成修复率证据。本轮只支持本案例集、模型与环境下的探索性结论，不据单次比例差宣称统计显著。

工具另用 10 个操作任务检查定位、确认、回退与报告，拟邀请 3—5 名学生试用，预先选 10 个错误评估案例交叉复核解释与引用。试用不评价长期教学效果。

## 人员分工

| 成员 | 职责与交付 |
| --- | --- |
| 张宇宸（组长） | 架构集成、文档索引与 BM25、模型及候选校验；交付检索修复模块、提示版本、协议与预算 |
| 石澄錡 | 编译诊断、执行隔离、测试与参考行为复核；交付验证模块、保留测试与判定记录 |
| 高远 | 任务历史、本地 Web、差异确认、回退报告、批量调度；交付交互入口、原始记录及配对汇总 |

三人共同做案例复核、接口评审及记录审计，记录开源复用范围和个人贡献。

## 八周检查节点

| 周次 | 目标 |
| --- | --- |
| 第 1 周 | 验证 SDK、模型、隔离与预算，明确研究问题及第三组定位 |
| 第 2 周 | 固定接口，联通界面定位，准备开发案例和协议草案 |
| 第 3 周 | 实现检索解释，统一两组输入、反馈和日志 |
| 第 4 周 | 贯通确认、测试、取消、原文件保护及批量记录 |
| 第 5 周 | 完成两轮、回退、报告、汇总及案例复核 |
| 第 6 周 | 完成功能与异常检查，冻结案例、配置、规则和版本 |
| 第 7 周 | 运行 A/B，候选锁定后验证，分析结果并试用 |
| 第 8 周 | 记录修复与复测影响，交付证据、局限说明和答辩 |

## 与第三组协作

第三组“仓颉程序学习助手”围绕知识点、练习推荐和教师统计；本组围绕诊断修复及受控评估。允许基础能力交叉，题库接入诊断、真实错误样本和共同试用均可协商，尚未形成承诺。冻结后新样本单列扩展集，不能改变原分母或泄露保留测试。

完整内容见 [正式报告](proposal.pdf)、[实验协议](experiment-protocol.md) 和 [定位说明](positioning-and-collaboration.md)。协作入口为 [GitCode](https://gitcode.com/A72316/cangjie-code-doctor)，[GitHub](https://github.com/Frank72316/cangjie-code-doctor) 保留同步副本。
