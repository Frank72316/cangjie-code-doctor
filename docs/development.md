## 预览与检查

仓库 PowerShell：

```powershell
./scripts/preview.ps1
# 打开 http://127.0.0.1:8765；Ctrl+C 停止。
# 已安装 Node.js 22+ 时也可直接运行：
node scripts/preview.mjs
node --test tests/viewer.test.mjs
```

端口冲突时可在当前 shell 设置 `$env:DOCTOR_PREVIEW_PORT = '8766'` 后启动，不修改系统环境。预览文件已经随仓库提供，不依赖本机仓颉程序能运行。

界面检查路径：选择类型错误 → 点击“第 2 行 · 24 列” → 修改源码 → 确认“未编译副本”且定位停用 → 恢复记录副本 → 选择正常程序 → 确认“编译通过”仍为“行为未验证”。打开原始日志可核对 cjc 原文。导出诊断记录保留**采集时**的源码，当前编辑副本应另行下载。

导入文件限 UTF-8、`.cj`、64 KiB、200 行；导入记录上限 2 MiB，核对记录中源码的 SHA-256。编辑器可以暂存超行数内容，下载前会再次检查。哈希只检查记录与源码的一致性，不是数字签名，也不证明记录来源可信。

## 编译与原生检查

```powershell
./scripts/build.ps1 -SdkRoot 'D:\Cangjie'
./scripts/test-native.ps1 -SdkRoot 'D:\Cangjie'
```

`build.ps1` 使用 `cjc -p src` 直接编译，避免依赖当前同样崩溃的 `cjpm`。它只在成功编译后替换 `target/debug/doctor.exe`。编译失败时旧产物可能仍保留，不能把旧文件存在当作本次构建成功。

原生入口：

```text
doctor --version
doctor --self-test
doctor parse <编译器原始JSON文件> <编译器退出码>
```

`parse` 只读取已有证据，不编译或运行源码。正常处理返回 0；参数错误返回 2；证据无法可靠判定返回 3。结果中区分 `compile_passed`、`compile_failed`、`tool_error`，始终保留 `testStatus: not_run`。此处的 `compile_passed` 只依据传入退出码及诊断，调用方还须确认进程正常完成、输出完整及产物有效。

cjc 1.0.5 的正确样例成功编译时输出为空；错误样例的 JSON 位于 stderr。空输出仅配合退出码 0 才可作为成功证据；异常退出、无诊断的失败和字段矛盾都归为工具异常。字段缺失或诊断数被截断时保留原始日志，不能凭展示出的少数行误判完整性。适配器只支持诊断使用的整数 JSON 标量，最大 1 MiB、64 层嵌套，不是通用 JSON 库。

本机 `test-native.ps1` 启动即退出 `-1073741819 / 0xC0000005`，未执行到自检，四个夹具的原生解析检查也未开始。详见[环境排查](environment.md)。

## 重新采集开发证据

```powershell
./scripts/capture-examples.ps1 -SdkRoot 'D:\Cangjie'
```

脚本只接受内置 4 个文件名，先核对 `examples/manifest.json` 中的 SHA-256。源码更改后会拒绝编译，须人工复核再更新清单。仓库通过 `.gitattributes` 固定 `.cj` 的 LF 换行，避免跨机器检出改变哈希。

每次新建 `runs/capture-<随机编号>/`，先复制已核对的源字节，再编译快照；检查原件哈希没有变化，保留 `record.json`、`compiler.json` 和产物。程序**不运行**。公开夹具只含样例相对名称，不含本地任务绝对路径；`runs/` 和 `target/` 均被 Git 忽略。

采集脚本的 30 秒编译等待和输出长度检查属于开发故障保护；输出长度是在读取后检查，且尚无受测的操作系统级资源隔离。它不是任意源码的安全编译服务。正式后端接入前仍须验证独立进程、子进程清理、内存/磁盘/网络/权限限制及取消处理。
