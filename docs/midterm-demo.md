## 真实案例采集

在已配置的Linux开发环境运行：

```bash
node scripts/capture-midterm-demo.mjs target/debug/doctor "$(command -v cjc)" "$DOCTOR_SANDBOX_IMAGE"
```

使用公开开发例type_mismatch：HTTP真实编译报错→SDK 1.0.5文档检索→固定修正 `"three"` 为 `3` →确认保存→受限容器公开测试（空输入，输出 `3\n`）→读取历史、修订与验证，确认原诊断未改写。脚本调用确认接口，是开发流程验收，不是学生操作、AI修复、保留测试或正式A/B。

每次生成独立 `runs/midterm-demo/<id>/`，包含总览index.html、初始诊断01-diagnosis.json、文档02-document-evidence.json、修订03-revision.json/html、验证04-verification.json/html和manifest.json。清单保留时间、版本、平台链接、步骤标识与文件哈希；全部断言通过才标记passed，失败保留错误。修订自身仍标记未验证，测试结论保存在独立验证报告中。

CI自动采集并上传midterm-development-evidence制品（保留30天，应及时下载本机备份）。Linux记录在Windows打开仍是历史回看。HTML可离线打开，初始诊断可在工作台「记录与报告」导入。

## PPT截图顺序

### 解释未通过，而不只展示成功（2026-11-16新增）

新一轮真实采集会增加“编译通过、输出不符”的故意错误开发候选：把原来的字符串改成整数 `4`，公开要求仍为输出 `3\n`，不更改期望去迁就候选。容器须真实编译/运行、原生字节判定为未通过并确认清理，随后才保存 `06-output-mismatch.json`、`07-output-mismatch-review.html` 和同时包含两条路径的 `08-outcomes-bundle.json`。是否采集成功以该提交 CI 与下载后的 manifest 为准。

在“已有报告回看”打开失败 JSON 或汇总包选择未通过项。输出不符的测试默认展开，显示期望、实际和显示文本首个差异的位置；换行、空格、回车和制表符会明确标注。位置按 Unicode 字符计算，不能当成原始字节偏移；UTF-8 替换后的显示文本即使相同，也不会覆盖原生字节未通过结论。实时验证页、历史回看和 HTML 报告使用相同提示。

答辩可讲：“这个候选能编译，但输出 4，与公开要求 3 不同，因此保留为未通过；成功和失败记录都可追溯。”两条路径是预设的公开开发验收，不是模型修复尝试、学生试用、A/B 对照或修复成功率，不能据此声称文档检索有增益。

### 在正式工作台回看完整流程（2026-11-16新增）

进入“记录与报告”，展开“已有报告回看”，选择真实采集目录中的 `04-verification.json`。该文件内嵌原诊断、已保存修改和所附文档，无需拆开多个 JSON。页面校验后展示四阶段卡片；展开公开测试即可查看空输入、期望和实际输出 `3\n`，并下载完整回看 HTML。只读回看不依赖本机仓颉运行时，不会把导入的报告写成本机运行历史。

也支持单份 `03-revision.json`（明确无后续验证）以及“存储与材料导出”生成的汇总包；汇总包中的多次验证分别选择，不汇总成成功率。来源不明的文件即使哈希一致也不等于经过认证，答辩仍须引用原采集 manifest 和 CI 页面。

本机 `output/midterm-demo/` 已准备便于选择的 `11-回看用真实验证记录.json`、`11-完整流程回看报告.html`、`11-回看操作说明.txt`、`review-receipt.json`，以及 `screenshots/11-evidence-review.jpg`。JSON 是先前 Linux CI 证据的原字节副本，核对原 manifest；HTML 浏览器下载与生成结果逐字节一致，不改写原采集时间。后续真实 CI 采集另输出 `05-workflow-review.html` 并登记哈希。

1. 正式工作台和功能入口，说明本组的诊断—修改—验证定位。
2. 导入本次真实诊断，展示第2行错误定位；配文标明Linux运行日期。
3. 修改报告展示字符串改为整数、官方文档引用与源码摘要；交互由用户确认，采集脚本演练同一接口。
4. 独立验证报告展示编译、公开输出比对、容器与清理结果。一个公开测试通过不证明所有输入正确。
5. 阶段边界：AI未接入、正式案例未齐全，工具检查与后续A/B分别汇报。

截图保留历史记录、未验证等关键状态。组员应解释模块与证据，不将Codex辅助产出记为个人独立贡献。

### 原始输出一致性（2026-11-16）

新容器报告的内层版本为2（外层验证记录仍为1）。每路输出嵌入规范Base64原字节，核对字节数、SHA-256与UTF-8替换显示；requestSha256按固定字段顺序绑定源码名称/正文、测试ID/输入/期望，原生精确字节比较必须与这些字节相符。服务读取、单份及汇总包导入使用同一校验，任一矛盾拒绝。HTML只由校验后的记录生成。

旧版仍可阅读，但显示“原始字节核验受限”；无替换字符的文本可核对长度及摘要，含替换字符且缺原字节时不能完整核对，不补造证据。新报告的绿色核验提示与测试成败分开，异常只核验已捕获部分。无签名摘要不能认证作者或阻止所有字段一致重写，不等于重新执行、AI修复或正式实验成绩。
