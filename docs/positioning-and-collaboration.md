# 与第三组的定位及合作说明

本说明根据教师反馈整理，日期为 2026-10-21。第三组的描述来自目前提供的“仓颉程序学习助手”定位；双方尚未共同确认详细接口、样本授权或协作安排。

## 各自回答什么问题

| 维度 | 本组诊断与测试验证工具 | 第三组程序学习助手 |
| --- | --- | --- |
| 核心对象 | 已有程序的诊断与修复流程 | 学生的知识理解及练习过程 |
| 主要流程 | 报错 → 文档依据 → 用户主导修改 → 测试验证 | 错误 → 知识点 → 练习推荐 → 教师统计 |
| 核心问题 | 同版本文档检索是否改变修复成功率 | 如何支持知识理解、练习与教学反馈；具体评价由第三组确定 |
| 本组的证明方式 | 冻结案例、同模型同参数 A/B、独立保留测试、配对结果及成本 | 不替第三组预设实验或承诺学习成效 |

两组可以共享中文解释、文档查询和错误定位等基础能力。区别在核心问题与证明方式，无须以排他性功能清单划分边界。本组仍须把定位、确认、回退、报告做好，确保受控实验有稳定载体。

## 可讨论的合作

1. 第三组在题库任务中试用本组诊断接口，双方先确认输入输出约定和题目授权。
2. 第三组或其他同学提供真实错误样本，经同意、去标识、题意核验及测试复核后纳入。冻结前按同源规则划分，冻结后单列扩展集。
3. 双方互相试用，记录操作困难。本组的试用与主 A/B 分开，不能向主实验泄露保留测试或添加人工修复反馈。

上述只是合作建议，没有宣称对方已经同意。后续讨论应书面记录各组的研究问题、交付内容、样本来源、授权范围及接口，不需要限制对方采用相似技术。

## 答辩表述

我们用仓颉实现稳定的诊断修复工具，并用受控实验考察同版本官方文档检索的增量作用。第三组围绕知识点与练习形成学习流程。两组可以共享样本和试用资源，但各自用适合自己问题的证据说明成果。本组的结论仅适用于本次案例集、模型及环境，检索结果无明显改善或下降时也完整报告。
