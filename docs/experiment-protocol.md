# 仓颉程序诊断助手 A/B 实验协议

版本日期：2026-10-21。本文为开题阶段方案，尚未冻结或执行。第二周细化配置，第六周在评估前登记版本及摘要；任何实际结果须在运行后填写。

## 研究问题与证据边界

在固定模型、SDK、环境与修复流程下，加入同版本官方文档检索，是否改变课程程序的修复成功率？检索提供的额外上下文与开销属于本次处理的一部分；本实验不单独区分“文档语义”与“上下文长度”的影响。

工具是实验执行与留痕的载体。定位、确认、回退、报告是独立的可用性要求。学生觉得好用不能替代修复率证据，检索未带来提升也不能抹去已完成的工具验收。

## 案例及冻结

计划 30 例，10 例开发、20 例评估。16 个错误评估案例中，语法、类型、作用域或接口误用各 4 例且初始编译失败；另 4 例能够编译但在公开测试中暴露逻辑错误。4 个正确案例单独检查回归行为，不调用模型自动改写，不纳入修复率分母。

每例登记 ID、来源与授权、同源题目 ID、题意、输入输出约定、错误类别、原代码、参考实现、公开测试、保留测试和文件摘要。两名成员交叉复核题意与参考行为；错误代码须在冻结环境下稳定暴露问题。原题及其同源变体整体进入同一划分，不能用评估变体调提示或检索参数。

公开测试可见，保留测试独立覆盖正常及边界行为。石澄錡负责保留测试和独立判定入口，另一成员复核。评估执行人员不得据其内容修改候选或筛选结果。保留测试及其预期输出不得出现在提示、检索索引、候选筛选界面或提前公开的仓库中。

第六周冻结并记录摘要：案例 ID 与划分、源码与测试、SDK 与镜像、依赖、官方文档快照、分段和 BM25 参数、提示模板、模型标识、采样参数、输出上限、请求超时、运行资源限制、输出比较规则、任务与调用顺序、工具提交、停止和重跑规则。所有待定配置须在主实验前填写，不使用评估成绩决定参数。

获授权的真实学生错误可在冻结前按同一规范纳入。冻结后新增样本建立扩展集，单列来源和结果，不改变原主实验分母。发现原案例实质缺陷时保留原记录并披露；如需修订，建立新版本并对两组一致处理，不能静默删例。

## 两组输入及执行

| 条件 | A 组 | B 组 |
| --- | --- | --- |
| 初始输入 | 题意、源码、公开测试、原始编译及公开测试结果 | 与 A 相同，额外附同版本官方文档片段 |
| 检索 | 关闭 | 按初始诊断、标识符及公开失败信息检索，片段在两轮中固定 |
| 后续反馈 | 自己上一候选的编译与公开测试反馈 | 同左 |
| 最大轮数 | 2 | 2 |
| 人工干预 | 不改候选，不追加提示，不挑选多个响应 | 同左 |

两组模型、参数、输出上限、提示骨架、可见任务信息、环境和判定规则一致。文档内容及相关引用要求随检索开关变化，引用检查不可使 A 组因缺少文档而被误判为响应非法。B 组检索为空也照常记录，不删除该例。

同一案例配对执行，两组调用尽量靠近；按冻结后的案例顺序交替采用 A→B 与 B→A。每个错误每组一次，计划最多 64 次生成请求。配对之间不共享对方候选或反馈，不使用跨任务记忆。记录实际时间、服务返回的模型标识、请求次数、输入输出用量和费用；服务不提供字段时标记缺失，不能记为零。

交互模式允许学生编辑、拒绝和回退。主实验为独立批量模式，按预定规则自动将候选副本送入隔离验证，不弹出人工择优环节；交互试用结果另表记录。

## 停止与候选选择

1. 首轮响应需满足固定结构、长度、代码及引用规则。格式有效时在受限环境编译，成功后运行全部公开测试。编译且公开测试全过即停止，保留本候选。
2. 首轮未通过时，在剩余预算内进入第二轮。编译或公开测试反馈按同一模板返回；格式非法时返回校验失败信息，不手工修补模型输出。
3. 最多两轮，最终保留最近一轮格式有效且含候选代码的响应。若第二轮无效，保留有效的首轮；两轮均无效则记无候选失败。不得查看保留测试后回选候选。
4. 完全无代码变化、统一预算耗尽或任务取消时按冻结规则终止，保留当时有效候选与原因；不能因此删除案例。首轮无有效候选而终止时记失败。
5. 首轮和最终候选分别登记。所有任务完成并锁定候选代码摘要后，才由独立验证入口读取保留测试。首轮指标如需保留测试评分，同样在全部候选锁定后进行，不能反馈给生成过程。

格式错误计入轮次和调用数，不选择性重试。确认的网络或服务故障可在恢复后对受影响的整个 A/B 配对统一重跑一次；旧记录与费用保留，新配对明确标记，不能挑较优一次入表。再次故障记工具或服务失败。计划的 64 次不含故障重跑，后者单列预算与实际成本。冻结时设置总费用上限；若达到上限而未完成计划，明确报告未完成数及原因，不把部分结果包装成完整实验。

## 判定及结果表

修复成功须同时满足：最终有效候选编译成功，且全部公开测试与保留测试通过。超时、异常、输出超限、无候选、未执行及工具故障均不能记为成功。原始计数完整披露，实际未完成的计划单元保留在主表中并标记。

模型不得改题意、测试预期值或比较规则。人工依据题意复核硬编码输出、删减功能和输入约定变化。测试判定与人工审查分别列出；疑似不满足题意的候选加注原因与证据，不能宣称“测试通过即语义完全正确”，也不能在看到组别结果后临时改变判据。

| 结果项 | 口径 |
| --- | --- |
| 主修复率 | A 成功数 / 16；B 成功数 / 16 |
| 配对结果 | 均成功、仅 A 成功、仅 B 成功、均失败，四格合计 16 |
| 成功率差 | B − A =（仅 B 成功数 − 仅 A 成功数）/ 16，以百分点报告 |
| 编译恢复 | 初始编译失败的 12 例中，最终编译成功数 / 12 |
| 逻辑修复 | 初始可编译的 4 个错误单列成功数 / 4 |
| 正确回归 | 4 个正确案例的诊断、执行及默认不改写行为，另表展示 |
| 运行开销 | 实际调用数、输入输出用量、费用、端到端耗时，另列重跑开销 |

逐案例主表字段固定为：案例 ID、类别、A/B 首轮状态、A/B 最终状态、终止原因、编译/公开/保留测试结果、候选摘要、人工审查、请求数、成本、耗时、故障及重跑关联。另附逐轮输入输出与检索证据。主表原始数据不填示例成绩。

本轮每组只运行一次，16 个错误中每变化一例就是 6.25 个百分点。报告精确计数与配对差异，不凭比例高低宣称统计显著，不从 4 例的分类结果推出稳定规律。第二轮提升只作描述，不能单独归因为反馈。在线模型可能变化，重新调用不保证相同输出；保存的原始记录应能确定性重算汇总。

## 预先约定的解释方式

- B 较高：陈述在本配置与案例集观察到的差值，同时披露失败和成本；不外推为所有仓颉程序或所有模型的优势。
- 两组接近：陈述“本次未观察到明确优势”，展示配对成败与具体案例；不能把“未见优势”说成证明普遍无效。
- B 较低：完整报告下降及代价，检查检索相关性、版本适配和干扰案例；不得删去负面案例、临时换分母或只展示有利错误类型。

检索不相关、任务过易、上下文干扰等只是待证实的可能解释，须结合日志核对。展示工具验收、冻结清单、对照记录和失败分析，不以预设提升幅度作为结项条件。

## 工具验收及发布

计划 10 个操作任务，覆盖定位、解释、确认或拒绝、回退、测试及报告，包含编译错误、运行异常、逻辑失败、正确程序和无测试场景。覆盖编译器不可用、解析不完整、检索为空、非法响应、断网、超时与输出超限。拒绝或取消不能改变导入文件，旧结果须绑定源码摘要，失败不能显示通过。

拟邀请 3—5 名非项目成员试用并记录完成情况与困难；从错误评估集预先选定 10 例，交叉复核解释、建议与引用，缺失或无效解释计入该项失败。试用在主实验候选锁定后进行，不向主实验提供人工反馈，不测长期学习成效。

保留测试本地路径约定为 `data/holdout/`，由独立评估入口访问，生成与检索进程不挂载该目录。忽略规则只是防误提交措施，不能替代权限隔离。公开前检查授权、密钥、个人路径和测试泄露；可公开复现材料的范围与保留测试解封另行登记。

影响结果的工具缺陷在评估后修复时，记录新提交、原因和受影响案例，对两组一致复测，原结果保留为旧版本。正式报告与结果材料必须说明使用哪一版本。
